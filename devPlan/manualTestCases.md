# 实测用例（需人工实机验证）

本文件登记**自动化覆盖不到、必须人工在游戏里看/操作才能确认**的项目（视觉观感、手感、音效、平衡、时序节奏等）。单测与冒烟（`tools/run_smoke.sh`）能证明的一律不进本文件。

## 维护规则

- 任务细化时，把本次新增的实测项按 `MT-###` 编号追加到「待验证」；编号递增，**不复用**。
- **任务不因等待实测而阻塞**：`dotnet build` 零 warning + 单测 + 冒烟通过即视为该任务施工完成并提交；实测项留在这里等用户验证。
- 验证通过 → 状态改 ✅ 并记日期，移到「已通过」；验证失败 → 改 ❌，把现象写进备注，另开修复任务。
- 工程性验证（build / 单测 / 冒烟 / `check_uids` / `check_architecture`）属于提交门禁，**不登记**在此。
- 「已通过」区保留最近一个版本周期，之后整段清理，保持本文件只含待验证与近期已通过项。
