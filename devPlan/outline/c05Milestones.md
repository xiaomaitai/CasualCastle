### P1 草地战场

当前战场为灰色单色背景。v0.1 替换为绿色草地场景：

- **草地底纹**：绿色草地 tile 或平铺纹理，覆盖整个战场区域
- **装饰草**：在草地上随机散布装饰性草丛精灵（静态，无碰撞），增加视觉层次
- **背景**：战场后方放置山和云的远景图片（ParallaxBackground 或静态 Sprite），形成纵深感
- 战场功能区域（玩家城堡、敌方城堡、中间交战区）位置不变

实现方式：
- 草地 tile：`TextureRect` 或 `TileMap` 平铺
- 装饰草：`MultiMeshInstance2D` 随机散布（性能友好）
- 山云背景：`ParallaxBackground` + `ParallaxLayer` + `Sprite2D`

### P2 建筑与通道系统

核心规则变更——建筑与格子的关系：

- **建筑占满格子**：一个建筑覆盖其占地范围内的所有格子，碰撞体贴合格子边缘
- **格间空隙**：相邻格子之间存在固定的通行间隙（约 15 游戏单位），单位可在空隙中行走
- **多格建筑不可穿越**：多格建筑内部所有格子连为一体，中间无通道，单位必须绕行
- **通行规则**：单位寻路时，已放置建筑的所有格子 + 建筑内部均为障碍物；格间空隙构成自然路径网络

对现有系统的影响：
- 建筑碰撞体从当前的"略小于格子"改为贴合格子边缘（100 游戏单位/格）
- 寻路导航网格（NavigationRegion2D / TileMap navigation layer）需随建筑放置/摧毁动态更新
- `OccupancyGrid` 逻辑不变——已占格子就是障碍物

格间空隙示意（俯视）：
```
┌──────┐ ┌──────┐
│ 建筑A │ │ 建筑B │
│ 2×2  │ │ 2×2  │
│      │ │      │
└──────┘ └──────┘
  ↑ 空隙 ↑ 空隙 ↑  ← 单位可通行
```

### P4 组合系统扩展

当前 M5 组合仅支持单格建筑（`IsCombinableMaterial` 检查 `Footprint.Length == 1`）。P4 扩展：

- 移除 `Footprint.Length == 1` 限制，允许多格建筑参与组合
- 多格建筑组合规则：主体与辅材的占地大小一致即可；结果建筑沿用主体占地
- 邻接判定适配多格：辅材的**任意格子**与主体的**任意格子**四向相邻即满足邻接条件
- 联盟 3 条配方：兵营+兵营→高级兵营、靶场+靶场→高级靶场、马厩+马厩→高级马厩
- 组合后结果满血、产兵进度清零、邻接刷新

### P5 邻接加成扩展

当前仅兵营有邻接加速。P5 扩展到所有联盟建筑：

| 建筑类型 | 邻接条件 | 效果 |

- 加成可叠加（两座互邻建筑各自获得 -15%）

### P6 数据层完善

当前 `config.db` 已存储建筑和单位定义。P6 扩展：

- `building_defs` 表新增联盟 6 条建筑记录（含 footprint JSON、组合阶数）

技术约定：数据存储统一使用 SQLite（`assets/data/config.db`），非必要不使用 `.tres` 资源文件或 `.tscn` 预制体存储配置数据。

### P7 存档与打磨

**存档系统**：

### B2 攻防克制表

**攻击类型（7 种）**：

| 编号 | 攻击类型 | 典型来源 |
|------|---------|---------|
| 1 | 挥砍 | 剑、斧 |
| 2 | 穿刺 | 矛、箭、弩 |
| 3 | 钝击 | 锤、棍 |
| 4 | 魔法 | 法术攻击 |
| 5 | 神圣 | 光系、净化 |
| 6 | 暗影 | 暗系、诅咒 |
| 7 | 真实 | 特殊（无视护甲） |

**护甲类型（7 种）**：与攻击类型一一对应命名。

**减伤公式**：

```
减伤率 = 护甲值 / (护甲值 + K)
```

- `K` 为常数（建议 K=100），使减伤率随护甲值递增但效果递减
- 示例：护甲 100 → 减伤 50%；护甲 200 → 减伤 66.7%；护甲 300 → 减伤 75%
- 克制关系通过护甲值修正实现：克制方攻击时目标等效护甲降低（如 ×0.5），被克制方攻击时目标等效护甲提高（如 ×1.5）
- 真实伤害无视护甲（等效护甲恒为 0）

**克制矩阵（7×7）**：待设计文档细化，基本原则：
- 每个攻击类型克制 1~2 种护甲、被 1~2 种护甲克制
- 克制关系形成循环而非单向链条

- 无缝纹理方案：
  - 程序化生成 3 张可平铺的基础纹理（草地、泥地、石板），边缘数学无缝
  - 使用 `TextureRect` 着色器平铺，并按周期噪声混合出泥地/石板区域
  - 装饰层（草、石子）用 `MultiMeshInstance2D` 随机散布，不依赖纹理接缝
- 摄像机：支持拖拽平移 + 滚轮缩放 + 边界限制（沿用 P7 摄像机方案）
- 城堡位置、交战区随战场扩大自适应调整

### B4 术语统一

全局替换：
- 兵种名词统一为「单位」（Unit）：旧词「士兵」「部队」不再使用
- 代码标识符统一为 `Unit` / `unit`（类名、变量名、方法名、节点名）
- 概念层新增「元素」（Element）作为地图实体总称，定义见 `concepts.md`

影响范围：
- domain 层：`Unit` 相关类型、方法、变量
- adapter 层：`UnitVisual`、`UnitLogic` 等 Godot 节点脚本
- 文档：`concepts.md`、所有 design 文档
- 场景/预制体命名

### B5 单位 AI 优化

当前单位 Bot 行为较简单（直线寻敌、正面碰撞）。B5 优化"小脑"能力：

- **寻路**：使用 `NavigationAgent2D` 实现平滑路径，绕过建筑和障碍物
- **目标选择**：统一取视野内距离最近的敌人；特殊目标逻辑只属于用户明确提出的特殊单位（如刺客）
- **包抄行为**：由寻路避让自然形成——接战单位原地站定成为避让障碍，后方行军单位经 RVO 绕开交战线从侧面包上，无主动包抄逻辑
- **避让友军**：移动时与友军保持最小间距，避免堆叠；接战/攻城单位原地站定不参与推开
- **状态机**：每个单位维护简单的行为状态（行军 / 索敌 / 接战）

### B6 特殊行动

部分单位拥有独特的特殊行动能力，在特定条件下触发：

**刺客 — 隐蔽渗透**：
- 能力：进入**隐身状态**，敌方单位无法将其作为攻击目标
- 触发：离敌方单位一定距离时自动进入隐身
- 行为：穿过敌方前排战线，直接移动到后排远程单位附近
- 破隐：攻击时显形；被 AOE 伤害命中时显形；敌方有反隐单位时无法隐身
- 限制：隐身期间移动速度略微降低

后续派系可扩展其他特殊行动（冲锋、嘲讽、治疗等）。
