### P1 草地战场

当前战场为灰色单色背景。v0.1 替换为绿色草地场景：

- **草地底纹**：绿色草地 tile 或平铺纹理，覆盖整个战场区域
- **装饰草**：在草地上随机散布装饰性草丛精灵（静态，无碰撞），增加视觉层次
- **背景**：战场后方放置山和云的远景图片（ParallaxBackground 或静态 Sprite），形成纵深感
- 战场功能区域（玩家城堡、敌方城堡、中间交战区）位置不变

实现方式：
- 草地 tile：`TextureRect` 或 `TileMap` 平铺
- 装饰草：`MultiMeshInstance2D` 随机散布（性能友好）
- 山云背景：`ParallaxBackground` + `ParallaxLayer` + `Sprite2D`

### P2 建筑与通道系统

核心规则变更——建筑与格子的关系：

- **建筑占满格子**：一个建筑覆盖其占地范围内的所有格子，碰撞体贴合格子边缘
- **格间空隙**：相邻格子之间存在固定的通行间隙（约 15 游戏单位），单位可在空隙中行走
- **多格建筑不可穿越**：多格建筑内部所有格子连为一体，中间无通道，单位必须绕行
- **通行规则**：单位寻路时，已放置建筑的所有格子 + 建筑内部均为障碍物；格间空隙构成自然路径网络

对现有系统的影响：
- 建筑碰撞体从当前的"略小于格子"改为贴合格子边缘（100 游戏单位/格）
- 寻路导航网格（流场，格子随建筑放置/摧毁动态重建并递增版本号）
- `OccupancyGrid` 逻辑不变——已占格子就是障碍物

格间空隙示意（俯视）：
```
┌──────┐ ┌──────┐
│ 建筑A │ │ 建筑B │
│ 2×2  │ │ 2×2  │
│      │ │      │
└──────┘ └──────┘
  ↑ 空隙 ↑ 空隙 ↑  ← 单位可通行
```

### P4 组合系统扩展

当前 M5 组合仅支持单格建筑（`IsCombinableMaterial` 检查 `Footprint.Length == 1`）。P4 扩展：

- 移除 `Footprint.Length == 1` 限制，允许多格建筑参与组合
- 多格建筑组合规则：主体与辅材的占地大小一致即可；结果建筑沿用主体占地
- 邻接判定适配多格：辅材的**任意格子**与主体的**任意格子**四向相邻即满足邻接条件
- 联盟 3 条配方：兵营+兵营→高级兵营、靶场+靶场→高级靶场、马厩+马厩→高级马厩
- 组合后结果满血、产兵进度清零、邻接刷新

### P5 邻接加成扩展

当前仅兵营有邻接加速。P5 扩展到所有联盟建筑：

| 建筑类型 | 邻接条件 | 效果 |
|---------|---------|------|
| 兵营 | 与兵营/高级兵营四向邻接 | 产兵间隔 -15% |
| 靶场 | 与靶场/高级靶场四向邻接 | 产兵间隔 -15% |
| 马厩 | 与马厩/高级马厩四向邻接 | 产兵间隔 -15% |

- 同类型建筑链（Tier 1 与 Tier 2 互认同类型）
- 加成可叠加（两座互邻建筑各自获得 -15%）
- 光环可视化沿用现有 `AdjacentLinkPulse`

### P6 数据层完善

当前 `config.db` 已存储建筑和单位定义。P6 扩展：

- `building_defs` 表新增联盟 6 条建筑记录（含 footprint JSON、组合阶数）
- `unit_stats` 表新增联盟 6 条单位记录（含伤害类型、护甲类型、体型）
- `combine_recipes` 表新增 3 条配方
- `damage_matrix` 表（新建）：4×4 伤害/护甲倍率矩阵
- `DamageMatrix.LoadFrom()` 从 SQLite 读取倍率数据，替换当前全 1.0 默认值
- 商店卡池表（新建）：每种建筑的商店出现权重与费用

技术约定：数据存储统一使用 SQLite（`assets/data/config.db`），非必要不使用 `.tres` 资源文件或 `.tscn` 预制体存储配置数据。

### P7 存档与打磨

**存档系统**：
- 保存内容：建筑布局（类型+格位+血量）、金币、昼夜轮次、当前手牌、关联战报 ID
- 保存时机：手动保存（暂停菜单）+ 自动保存（每天开始时）
- 存储格式：SQLite 数据库（`user://saves/`，一个存档一个 `.db` 文件）
- 读取：标题界面「继续游戏」按钮，读取最新存档恢复游戏状态

**摄像机系统**：
- 中键或右键拖拽平移
- 边界限制（摄像机不超出战场范围）
- Home 键重置视角

**平衡打磨**：
- 基于测试数据调优产兵间隔、单位属性、金币经济
- 伤害矩阵在实战中验证并调整倍率

### A2 战斗表现深化

当前战斗缺乏视觉反馈——弹体不可见、无受击/死亡特效、皇家兵种特殊能力没有视觉区分。

**弹体可视化：**
- 远程单位（弓箭手/弩手/神射手）发射可见弹体
- 弹体：小型 Sprite2D，从攻击方飞向目标，命中后消失
- 弹体速度 = 攻击方到目标距离 / 0.3s（快速但不瞬间）
- 弹体命中时触发目标受击闪白（已有 `UnitVisual` 受击闪白能力）

**死亡特效：**
- 单位 HP 归零时播放消散动画（0.3s 淡出 + 缩小）
- 建筑摧毁时播放碎片/烟尘粒子

**皇家兵种能力视觉（已砍掉）：**
- 不做单个兵种的复杂特效，保持简洁

**实现要点：**
- 弹体：`Projectile` 预制体（Area2D + Sprite2D），由 `UnitLogic` 或 `BattleManager` 管理
- 死亡动画：`UnitLifecycle` 扩展淡出逻辑
- 能力特效：程序化粒子/刀光，不依赖外部素材

**验收标准：**
- [ ] 远程单位发射可见弹体，命中后消失
- [ ] 单位死亡有淡出消散动画
- [ ] 皇家兵种能力有视觉区分

### B3 大战场与无缝纹理

- 战场尺寸扩大为 3840×2160（2 倍设计分辨率），超出屏幕范围时可**拖拽滑动**查看

  - 程序化生成 3 张可平铺的基础纹理（草地、泥地、石板），边缘数学无缝

- 摄像机：支持拖拽平移 + 边界限制（沿用 P7 摄像机方案）

### B5 单位 AI 优化

当前单位 Bot 行为较简单（直线寻敌、正面碰撞）。B5 优化"小脑"能力：

- **寻路**：流场寻路 + 局部转向（SC2 式）实现平滑路径，绕过建筑和障碍物
- **目标选择**：统一取视野内距离最近的敌人；特殊目标逻辑只属于用户明确提出的特殊单位（如刺客）
- **包抄行为**：由流场 + 软分离自然形成——接战单位原地站定成为避让障碍，后方行军单位绕开交战线从侧面包上，无主动包抄逻辑
- **避让友军**：移动时与友军保持最小间距，避免堆叠；接战/攻城单位原地站定不参与分离
- **状态机**：每个单位维护简单的行为状态（行军 / 索敌 / 接战）

### B6 特殊行动

部分单位拥有独特的特殊行动能力，在特定条件下触发：

**刺客 — 隐蔽渗透**：
- 能力：进入**隐身状态**，敌方单位无法将其作为攻击目标
- 触发：离敌方单位一定距离时自动进入隐身
- 行为：穿过敌方前排战线，直接移动到后排远程单位附近
- 破隐：攻击时显形；被 AOE 伤害命中时显形；敌方有反隐单位时无法隐身
- 限制：隐身期间移动速度略微降低

后续派系可扩展其他特殊行动（冲锋、嘲讽、治疗等）。

### E1 音频架构

当前音频是单曲硬编码：`BgmPlayer` 在标题与主战场场景各挂一个节点。E1 建立统一音频架构：

- 音频总线：`Master` → `Music`、`SFX` 两条子总线，音量分别控制
- 新增 `AudioManager`（autoload，`scripts/adapters/godot/audio/`），负责 BGM 播放/切换/交叉淡化与 SFX 一次性播放，经 AdapterRegistry 注册
- 移除两个场景中散落的 `BgmPlayer`，BGM 统一由 AudioManager 接管
- 音频完全属于 adapter 层，不依赖 domain

### E2 BGM 系统

BGM 采用**曲目池轮播**：播放完一首 → 静默 3~6 秒 → 播下一首；池内默认随机（不立刻重复刚播过的曲），顺序播放可配置。

| 曲目池 | 使用场景/状态 | 数量 |
|--------|-------------|------|
| 标题池 | 标题 | 3 |
| 联盟·白天池 | 主战场·联盟·白天（含叠加状态） | 3 |
| 联盟·夜晚池 | 主战场·联盟·夜晚 | 2 |
| 部落·白天池 | 主战场·部落·白天 | 3 |
| 部落·夜晚池 | 主战场·部落·夜晚 | 2 |
| 结算池 | 结算 | 2 |

- 主战场曲目按**派系 × 昼夜**分组：联盟/部落白天、夜晚曲风可区分；派系由存档/标题选择决定
- 场景/状态切换（标题→对局、白天↔夜晚、结算）约 1 秒交叉淡化，避免硬切爆音；池内切换用静默间隔衔接
- 暂停/商店/放置/设置不换池，跟随当前主状态
- 曲目池与曲目引用集中在 AudioManager，场景内不再硬编码资源路径
