# 当前任务：冒险者公会——酒馆组队系统

阶段说明：联盟最后一个流派收尾。数据层已落地（4 座公会 + 酒馆 + 8 种兵种、商店卡池、`unit_stats.race` 字段、鱼龙混杂闪避），本期实现酒馆组队逻辑与酒馆对话气泡交互。设计基准见 `devPlan/design/factions/allianceFaction.md` 第 4 章。v0.7 建筑美术按用户决定整体延后，不在本期范围。

调研发现的前置缺口：`upgrade_recipes` 与 `tech_tree_nodes` 缺少公会线与酒馆→冒险者公会的升级边（游侠公会→风行圣殿、战士公会→山丘要塞、盗贼行会→暗影公会、术士高塔→龙火塔、酒馆→冒险者公会），T2 冒险者公会（6 槽）当前不可达，本期一并补齐。

## 一、组队规则（domain 层，纯 C#）

- 新增 `scripts/domain/Battle/TavernPartyService.cs`（含规则类）：维护每座酒馆的等待名单；槽位上限 T1 酒馆 4、T2 冒险者公会 6
- 公会产出的冒险者（race ∈ Elf/Dwarf/Halfling/Dragonborn）：场上存在我方酒馆时前往**最近酒馆**集结；无酒馆照常上前线
- 同族去重：每个种族只入馆 1 人；等待名单中已有该种族时，后续同族不进入酒馆、正常上前线
- 不同种族数达到上限 → 全队出发：名单清空，所有等待单位恢复行军（目标敌方城堡）
- 等待单位不索敌、不攻击、不推进；夜间休眠沿用现有休眠逻辑；死亡后从等待名单移除
- `UnitState` 增加 `Waiting` 状态；`UnitLogic.SelectTarget` 按单位等待状态返回酒馆站立点或敌方城堡
- 服务注册进 `CompositionRoot` 的 DI 容器；酒馆类型集合、槽位上限等常量进 `GameRules` 或服务内命名常量，禁止魔术数字

- [ ] T2 冒险者公会槽位上限为 6

## 二、酒馆对话气泡（adapter UI 层）

- 视觉：漫画式**对话气泡**（圆角气泡 + 指向酒馆的尾巴），不是面板/框体；锚定在所选酒馆上方并跟随建筑位置，不放 UI CanvasLayer
- 新节点 `scripts/adapters/godot/ui/TavernBubble.cs`（Node2D，`_Draw` 绘制气泡与尾巴；槽位用 `Area2D` + 输入事件或坐标命中检测实现点击），挂在所选酒馆的 `Effects` 下
- 显示时机：玩家**选中**酒馆且名单非空时出现（接 `UnitSelectionController` 的选中/取消选中）；取消选中自动隐藏，无需关闭按钮、Esc 或点空白关闭
- 槽位：N 个槽（T1 酒馆 4、T2 冒险者公会 6），空白槽显示空背景；已占槽显示该种族代表冒险者的头像（复用 `assets/art/cards/<TypeId>_*.png`，与 `AttributePanelController` 头像加载一致）
- 交互：点击已占槽头像 → 将该冒险者提前弹出（恢复上前线），气泡实时刷新；播放现有 UI 点击音效
- 名单变化（加入/出发/弹出/死亡）时气泡内容刷新；酒馆被摧毁或名单变空时气泡隐藏

验收项：

- [ ] 选中酒馆且名单非空时，酒馆上方出现漫画式对话气泡（带尾巴、非框体），显示 N 个槽
- [ ] 槽位为空白或冒险者头像；点击头像将对应冒险者提前弹出并恢复上前线，气泡刷新
- [ ] 取消选中、名单变空或酒馆被摧毁时气泡自动隐藏，无需手动关闭
- [ ] 气泡不遮挡放置/商店/手牌操作，输入不与其他面板冲突

## 三、adapter 行为接线

- `Building.SpawnUnits`：产出冒险者单位后调用 `TavernPartyService.TryAssignTavern(unit)`（最近酒馆）；酒馆本身 `production_rate=0` 不产兵
- `UnitLogic`：等待状态不执行索敌/攻击/推进（`_PhysicsProcess` 与 `UpdateTargeting` 分支），站立点取酒馆中心附近；出发/弹出后恢复敌方城堡行军
- `Building` 增加酒馆判定（`TavernPartyService.IsTavernBuilding(TypeId)`），供气泡显示与集结逻辑复用
- `UnitSelectionController`/`UIManager`：选中酒馆且名单非空 → 挂载并显示气泡；取消选中/酒馆摧毁 → 隐藏气泡（气泡节点随选中建筑挂载，无持久 UI 层）
- 战报回放敌方不做组队逻辑（敌方单位按战报复刻，不参与酒馆集结）
